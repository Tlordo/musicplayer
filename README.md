# YouTube Audio Library Manager 2.0 (Rust)

Локальная медиатека и плеер для музыки с YouTube / YouTube Music. Один исполняемый файл на Rust:
HTTP-сервер, база SQLite и веб-интерфейс встроены в бинарник. Внешние зависимости — только
[yt-dlp](https://github.com/yt-dlp/yt-dlp) и [FFmpeg](https://ffmpeg.org/).

## Что нового по сравнению с версией на Node.js

| | Было (Node.js) | Стало (Rust) |
|---|---|---|
| Запуск | `npm install` + Node.js + `node_modules` | один бинарник, интерфейс встроен |
| Загрузка | HTTP-запрос висит до конца скачивания, прогресс-бар — декорация | очередь загрузок, параллельные скачивания, живой прогресс через SSE, отмена |
| Плейлисты/альбомы YouTube | не поддерживались (ломали загрузку) | ссылка на плейлист раскрывается в отдельные треки; можно вставить несколько ссылок сразу |
| Перемотка | не работала (не было HTTP Range) | Range-запросы, перемотка в любом браузере |
| База данных | sql.js в памяти, весь файл перезаписывается при каждом изменении | нативный SQLite (WAL), транзакции, миграции |
| Безопасность | `video_id` из URL шёл прямо в путь к файлу | ID проверяется, path traversal невозможен; по умолчанию сервер слушает только `127.0.0.1` |
| Волновая форма | случайные столбики | настоящая, считается из аудио через FFmpeg, по ней можно перематывать |
| Восстановление | повторное скачивание с жёстко зашитого music.youtube.com, параллельные дубли | по исходной ссылке, без дублей, плеер сам продолжит воспроизведение; при потере БД библиотека восстанавливается из `*.track.json` |
| Плеер | индексы массива (ломались после удаления/сортировки), «Добавить в очередь» падало с ошибкой | очередь «играть следующим», честное перемешивание без повторов, история «назад» |
| Ещё | — | избранное, плейлисты (drag & drop), редактирование тегов, счётчик прослушиваний, «Недавние», таймер сна, скорость, Media Session (кнопки клавиатуры/экран блокировки), запоминание позиции, горячие клавиши, вставка ссылки через Ctrl+V, офлайн-иконки |

Старая база `database.db` (таблицы `techData`/`userData`) **импортируется автоматически** при первом запуске,
файлы в `Data/Music` и `Data/Info` используются как есть.

## Установка

1. **Rust** (для сборки): <https://rustup.rs>
2. **yt-dlp** — любой способ:
   ```sh
   pip install "yt-dlp[default]"   # или: winget install yt-dlp / brew install yt-dlp
   ```
   Пакет `[default]` включает `mutagen`, нужный для встраивания обложки в `.opus`.
3. **FFmpeg** — установите в систему (`winget install ffmpeg`, `brew install ffmpeg`, `apt install ffmpeg`)
   или, как раньше, положите `ffmpeg`/`ffmpeg.exe` в папку `ffmpeg/` в корне проекта.
4. Сборка и запуск:
   ```sh
   cargo run --release
   ```
   Готовый бинарник — `target/release/musicplayer(.exe)`. Плеер откроется по адресу <http://localhost:3000>.

### Docker

```sh
docker build -t musicplayer .
docker run -p 3000:3000 -v "$PWD/library:/data" musicplayer
```

### Cookies

Для контента, доступного только авторизованным пользователям, положите экспортированный из браузера
`cookies.txt` в корень проекта (или укажите путь через `--cookies`). Файл в `.gitignore` — не коммитьте его.

## Параметры

Все параметры можно задать флагом или переменной окружения (`musicplayer --help`):

| Флаг | Переменная | По умолчанию | Описание |
|---|---|---|---|
| `--host` | `HOST` | `127.0.0.1` | `0.0.0.0` — открыть плеер для телефона в локальной сети |
| `--port`, `-p` | `PORT` | `3000` | порт |
| `--data-dir` | `MUSIC_DATA_DIR` | `Data` | каталог с `Music/` и `Info/` |
| `--db` | `MUSIC_DB` | `database.db` | файл SQLite |
| `--ytdlp` | `YTDLP_PATH` | `yt-dlp` | путь к yt-dlp |
| `--ffmpeg` | `FFMPEG_PATH` | `ffmpeg/ffmpeg` или из `PATH` | путь к FFmpeg |
| `--cookies` | `COOKIES_PATH` | `cookies.txt`, если есть | файл cookies |
| `--parallel` | `MUSIC_PARALLEL` | `2` | сколько треков качать одновременно |

Подробность логов — через `RUST_LOG`, например `RUST_LOG=musicplayer=debug`.

> ⚠️ У сервера нет авторизации. Открывая его в сеть (`--host 0.0.0.0`), помните: любой в этой сети
> сможет добавлять и удалять треки.

## Горячие клавиши

`Пробел` — пауза, `←/→` — перемотка 5 с (`Shift` — 30 с), `↑/↓` — громкость, `N`/`P` — следующий/предыдущий,
`0…9` — переход к 0…90 %, `S` — перемешивание, `R` — повтор, `L` — в избранное, `M` — без звука,
`Q` — очередь, `V` — визуализатор, `B` — панель библиотеки, `/` — поиск, `A` — добавить, `?` — справка.

## Хранение данных

```
Data/Music/{id}.opus        аудио (Opus, встроенные теги и обложка)
Data/Info/{id}.jpg          обложка
Data/Info/{id}.track.json   резервная копия метаданных (по ней восстанавливается библиотека)
database.db                 SQLite: треки, плейлисты, статистика
```

## HTTP API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/add` | `{ "url": "..." }` или `{ "urls": [...] }` — поставить в очередь (202, список задач) |
| `GET` | `/api/library` | все треки с метаданными |
| `GET` / `PATCH` / `DELETE` | `/api/tracks/{id}` | трек; `PATCH` принимает `title`, `artist`, `album`, `favorite` |
| `POST` | `/api/tracks/{id}/play` | засчитать прослушивание |
| `POST` | `/api/tracks/{id}/restore` | заново скачать пропавший файл |
| `GET` | `/api/tracks/{id}/waveform` | волновая форма `{ "bars": [0..255] }` |
| `GET` | `/api/tracks/{id}/download` | скачать файл с именем «Исполнитель - Название.opus» |
| `GET` | `/api/stream/{id}` | поток аудио (HTTP Range); если файла нет — запускает восстановление |
| `GET` | `/api/thumbnail/{id}` | обложка |
| `GET` / `DELETE` | `/api/jobs` | список загрузок / очистить завершённые |
| `DELETE` | `/api/jobs/{id}` | отменить загрузку |
| `GET` | `/api/events` | Server-Sent Events: прогресс загрузок и изменения библиотеки |
| `GET` / `POST` | `/api/playlists` | плейлисты / создать `{ "name": "..." }` |
| `PATCH` / `DELETE` | `/api/playlists/{id}` | переименовать / удалить |
| `POST` / `PUT` | `/api/playlists/{id}/tracks` | добавить `{ "video_id" }` / задать порядок `{ "video_ids": [...] }` |
| `DELETE` | `/api/playlists/{id}/tracks/{video_id}` | убрать трек из плейлиста |
| `GET` | `/api/stats`, `/api/health` | статистика и проверка работоспособности |

Старый `DELETE /api/track/{id}` продолжает работать.

## Разработка

```sh
cargo test                       # модульные и HTTP-тесты
cargo clippy --all-targets
```

В debug-сборке файлы из `public/` читаются с диска — правки интерфейса видны без перекомпиляции.

Структура:

```
src/main.rs      запуск, проверка yt-dlp/ffmpeg, graceful shutdown
src/config.rs    параметры командной строки
src/api.rs       HTTP API и встроенный интерфейс
src/db.rs        SQLite: схема, миграции, импорт старой базы
src/jobs.rs      очередь загрузок
src/ytdlp.rs     работа с yt-dlp
src/waveform.rs  волновая форма через ffmpeg
public/          веб-интерфейс (HTML/CSS/JS, Font Awesome локально)
```
