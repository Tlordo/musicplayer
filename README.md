# Моя музыка

**Собственная медиатека из YouTube — на твоём диске, навсегда.**

Вставь ссылку — сервер на Rust скачает звук в Opus с обложкой и метаданными,
а плеер с двумя дизайнами сыграет его на компьютере, телефоне и даже без сети.

## ✨ Почему это не очередной стриминг

|  |  |
|---|---|
| 💾 **Всё твоё** | Каждый трек — файл `.opus` на твоём устройстве. Никаких подписок и исчезающих песен. |
| 🩹 **Самовосстановление** | Удалил файл случайно? Сервер сам скачает его заново при следующем воспроизведении. |
| 🏷️ **Порядок из коробки** | Название, исполнитель, альбом, дата и обложка извлекаются автоматически и лежат в SQLite. |
| 📱 **Телефон — главный экран** | Открой плеер с телефона по Wi‑Fi, добавь на экран «Домой» — и он работает как приложение. |
| ✈️ **Играет без компьютера** | Сохранённые треки и умный кэш продолжают играть, даже когда сервер недоступен. |
| 🎨 **Два мира** | Тёмная «Классика» и тёплая «Кассета» МК‑60 — переключаются на лету, музыка не прерывается. |

## 🎧 Возможности

### Два дизайна

<table>
<tr>
<td width="50%" valign="top">

#### 🖤 Классика
Тёмный, обложки в списке, крупная обложка над размытым фоном из неё же, настоящая форма волны трека для перемотки и спектр.

</td>
<td width="50%" valign="top">

#### 📼 Кассета
Библиотека — вкладыш МК‑60, заполненный от руки; плеер — кассета из дымчатого пластика рядом с обложкой, перемотка пальцем по окошку, счётчик, флуоресцентный индикатор уровня.

</td>
</tr>
</table>

Переключаются в настройках (шестерёнка) без остановки музыки. Для каждого — темы‑пресеты и **свои темы**: редактор цветов с живым просмотром, экспорт/импорт в JSON, цвета из обложки.

### Библиотека

- 🔎 **Поиск по названию** — в окне «Добавить трек» можно не искать ссылку, а написать «исполнитель — песня»: плеер найдёт трек на YouTube Music (или YouTube), любой результат скачивается кнопкой «+».
- 💿 **Альбомы** — свои подборки (создать, переименовать, «В альбом…» из меню трека) и альбомы, собранные автоматически по метаданным YouTube. Целый альбом или плейлист скачивается по одной ссылке, прогресс виден в углу.
- ❤️ **Любимое и умные подборки** — «Любимое», «Чаще всего», «Давно не слушал», «Ещё не слушал»; сортировка «чаще слушаю».
- 🧭 **Рекомендации** — YouTube‑микс по текущему треку, добавление одной кнопкой. В классике — вкладка рядом с библиотекой, в кассете — «сторона Б» вкладыша.
- 📤 **Перенос между устройствами** — кнопка «Скачать» на странице альбома отдаёт `.zip` (музыка, обложки, `manifest.json`). На другом устройстве «Альбомы → Импорт» — треки появятся без повторного скачивания.

### Воспроизведение

- 📋 **Очередь** — зажмите трек (на компьютере — правый клик): «Играть следующим», «В конец очереди», «В любимое», «В альбом», «О треке», «Скачать», «Удалить». Окно «Очередь» (⋯ или <kbd>Q</kbd>) можно переставлять и чистить. «Назад» возвращает к тому, что реально играло, а «вперемешку» не повторяет треки, пока не прозвучит весь список.
- 🎚️ **Звук** — плавный переход между треками (0–12 с), выравнивание громкости по EBU R128 до −14 LUFS, пятиполосный эквалайзер с пресетами и мягкий ограничитель, чтобы не хрипело.
- 🎤 **Текст песни** — встроенный [musetext](public/musetext): кинетическая типографика по синхронизированному тексту из LRCLIB. Слова идут поверх плеера, обложка и кнопки остаются на виду.
- 😴 **Таймер сна** — 10–90 минут или «до конца трека»; последние 20 секунд звук плавно затихает.
- 📊 **Статистика** — время и число прослушиваний, график по дням и месяцам, топ треков и исполнителей за 7 / 30 дней / год / всё время. Общая для телефона и компьютера.

### ✈️ Без компьютера

Музыка не останавливается, когда телефон теряет компьютер — ушли из дома, компьютер уснул.

- **«Сохранить на телефон»** — в меню трека, на странице альбома и «Сохранить «Любимое»» в настройках. Файлы, обложки и форма волны хранятся в IndexedDB; у сохранённых треков — значок телефона.
- **Умный кэш** — пока музыка играет в Wi‑Fi, на телефоне держатся текущий и 3 следующих трека очереди. Предел 100 МБ … 3 ГБ, старое вытесняется само; сохранённое вручную лимит не трогает.
- **Связь** — плеер раз в 25 с проверяет сервер. Без связи — плашка «Компьютер недоступен — играю сохранённое», несохранённые треки пропускаются, прослушивания копятся и уходят на сервер потом. Сервер вернулся — трек продолжается с того же места.

<details>
<summary><b>Как это работает по <code>http://&lt;ip&gt;:3000</code> и как открыть плеер вообще без сети</b></summary>

<br>

Браузеры дают сервис‑воркер только в защищённом контексте (HTTPS или localhost), поэтому по адресу в локальной сети его нет. Сохранение и игра без связи от этого не зависят: IndexedDB доступна и по http, а плеер сам подставляет сохранённый файл (blob‑ссылкой — перемотка работает). Чего без сервис‑воркера не будет — заново открыть плеер, пока компьютер недоступен: вкладку (или установленную иконку) нужно не закрывать. Чтобы работало и это:

- **Android, Chrome** — `chrome://flags/#unsafely-treat-insecure-origin-as-secure` → вписать `http://<ip>:3000` → Enabled → перезапустить Chrome. Сервис‑воркер (`public/sw.js`) включится: оболочка откроется без сети, а `/api/stream/:id`, `/api/thumbnail/:id`, `/api/peaks/:id` сохранённых треков он отдаёт из IndexedDB сам, с поддержкой `Range` (206).
- **Android‑приложение** (`android/`) держит свой сервер прямо в телефоне — ему компьютер не нужен вовсе.
- Самоподписанный HTTPS не помогает: Chrome не регистрирует сервис‑воркер на сайте с недоверенным сертификатом, а ставить свой корневой сертификат на телефон — хуже, чем флаг выше.

</details>

## 🛠 Запуск из исходников

**Нужно:** [Rust](https://rustup.rs), [yt-dlp](https://github.com/yt-dlp/yt-dlp) и [FFmpeg](https://ffmpeg.org).

```bash
git clone https://github.com/Tlordo/musicplayer
cd musicplayer
cargo run --release
```

Открой **http://localhost:3000** 🎉

| Режим | Команда |
|---|---|
| Только сервер | `cargo run --release` |
| С окном (WebView2 / WebKitGTK) | `cargo run --release --features desktop --bin mk60-desktop` |

<details>
<summary><b>Где сервер ищет yt-dlp и ffmpeg</b></summary>

<br>

- **yt-dlp:** `YTDLP_PATH` → `./yt-dlp(.exe)` → `./bin/yt-dlp(.exe)` → `PATH`
- **ffmpeg:** `FFMPEG_PATH` → `./ffmpeg/ffmpeg(.exe)` → `PATH`

**Авторизация (необязательно):** положите `cookies.txt` с куками браузера в корень проекта — тогда можно скачивать контент, доступный только авторизованным пользователям.

</details>

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `MUSIC_ROOT` | текущая папка | Где лежат `public/`, `Data/`, `database.db` |
| `COOKIES_PATH` | — | Путь к `cookies.txt` |
| `MAX_DOWNLOADS` | `2` | Сколько загрузок идёт одновременно |
| `RUST_LOG` | — | Уровень логов |

### Сборка приложений

| Платформа | Команда | Результат |
|---|---|---|
| 🪟 Windows | `powershell -ExecutionPolicy Bypass -File tools\package-windows.ps1` | `dist\MyMusic-Windows\` и `.zip` |
| 🐧 Linux | `bash tools/package-linux.sh` | `dist/MyMusic-Linux.tar.gz` |
| 🤖 Android | `cd android && ./gradlew :app:assembleRelease` | `.apk` — [инструкция](android/README.md) |
| ☁️ GitHub Actions | Actions → **build** → Run workflow | Все три сразу; с версией или тегом `v*` — в Releases |

> На Windows без Visual Studio C++ добавьте `-Toolchain stable-x86_64-pc-windows-gnu`. Зависимости Linux перечислены в начале скрипта.

### Тесты интерфейса


Playwright гоняет `public/` без сервера на Rust — API подменяется в тестах.

## 🔌 API

<details>
<summary><b>Треки</b></summary>

<br>

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/add` | Добавить трек: `{ "url": "..." }` |
| `GET` | `/api/search?q=…` | Найти трек на YouTube по названию |
| `GET` | `/api/library` | Вся библиотека с метаданными (`plays`, `last_played`, `liked`, `liked_at`…) |
| `GET` | `/api/stream/:video_id` | Потоковое аудио (Range, ETag, Last‑Modified) |
| `GET` | `/api/thumbnail/:video_id` | Обложка |
| `GET` | `/api/peaks/:video_id` | Форма волны (160 значений 0…1) и `loudness` в LUFS |
| `POST` | `/api/track/:video_id/play` | Отметить прослушивание: `{ "seconds" }` |
| `POST` | `/api/track/:video_id/like` | Избранное: `{ "liked": true \| false }` |
| `DELETE` | `/api/track/:video_id` | Удалить трек из базы и с диска |

</details>

<details>
<summary><b>Альбомы, импорт и экспорт</b></summary>

<br>

| Метод | Путь | Описание |
|---|---|---|
| `GET` `POST` | `/api/albums` | Список / создать: `{ "name", "tracks": [video_id…] }` |
| `PATCH` `DELETE` | `/api/albums/:id` | Изменить / удалить альбом |
| `POST` | `/api/albums/:id/tracks` | Добавить трек в альбом |
| `DELETE` | `/api/albums/:id/tracks/:video_id` | Убрать трек из альбома |
| `GET` | `/api/albums/:id/export` | Архив альбома `.zip` |
| `GET` | `/api/export?name=&ids=a,b` | Архив из произвольных треков |
| `POST` | `/api/import` | Импорт архива (тело — сам `.zip`) |
| `POST` | `/api/add-playlist` | Скачать альбом/плейлист в новый альбом: `{ "url" }` |
| `GET` | `/api/jobs` | Прогресс фоновых задач |

</details>

<details>
<summary><b>Статистика и рекомендации</b></summary>

<br>

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/stats?days=30&tz=180` | `plays`, `seconds`, `tracks`, `top_tracks`, `top_artists`, `recent`, `days`; `tz` — смещение пояса в минутах |
| `GET` | `/api/recommendations?seed=:video_id` | YouTube‑микс по треку (без `seed` — по трём последним добавленным), без того, что уже в библиотеке. `&fresh=1` — мимо кэша |

</details>

Трек засчитывается прослушанным, если прозвучала половина его или 30 секунд. Если файл пропал, `/api/stream` отвечает `404 { "restoring": true }` и восстанавливает трек в фоне.

## 🗂 Где лежат данные

```
📁 Data/
├── 📁 Music/      аудио в .opus
└── 📁 Info/       метаданные .json и обложки .jpg
🗄️ database.db     SQLite — вся медиатека, альбомы, статистика
```

---

<details>
<summary><b>🚀 Что улучшено по сравнению со старой Node‑версией</b></summary>

<br>

- Перемотка работает: стриминг и обложки поддерживают HTTP Range, ETag и Last‑Modified.
- Трек скачивается одним вызовом yt-dlp вместо двух.
- Настоящая SQLite (WAL, транзакции) вместо перезаписи всей базы после каждого изменения; старый `database.db` открывается как есть.
- `video_id` проверяется — нельзя прочитать или удалить файлы вне `Data/` через `../`.
- Повторное восстановление одного трека не запускается дважды; число параллельных загрузок ограничено.
- Обложки скачиваются атомарно (без битых файлов при обрыве), предпочитается JPG вместо WebP.
- Удаление трека убирает и его `*_user_info.json`; удаление несуществующего трека отвечает 404.
- `cookies.txt` стал необязательным.

</details>
